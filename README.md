# Formulation AI Platform · AdheFormAI

面向胶粘剂 / 电子封装材料配方研发的智能设计平台。

**核心立场**：不做一次性的黑盒性能预测，而是交付一套「**预测 → 推荐 → 实验 → 反馈**」的持续收敛闭环——用更少的实验轮次找到满足多目标约束的配方，并保证每一次输出都可解释、可追溯、可审计。

## 架构速览

```
L1 用户交互层     配方工作台 · 逆向设计台 · 实验管理 · 知识中心 · 系统管理
L2 应用服务层     预测 · 优化 · 主动学习 · 生成 · 项目/权限/审计（编排网关）
L3 AI 核心引擎    特征工厂 · 多任务预测 · 不确定性 · 优化/AL · 生成 · 生命周期
L3' 数据中台      配方/性能库 · 原材料库 · 文献/专利 · 版本血缘 · 质量校验
L4 基础设施       计算/GPU · 对象存储 · 模型仓库 · LIMS/ELN · 监控告警
```

分层之外，还有三条贯穿主线用于架构走查：**控制面**（版本/权限/灰度/审计）、**数据面**（特征/预测/结果/血缘）、**实验面**（推荐/执行/回写/重训）。任何新增需求都应能回答「落在哪个面、跨了几个面、跨面一致性如何保证」。

### 五条硬约束

1. 样本稀缺且昂贵（10²–10³ 量级，且偏向成功配方）
2. 配方即核心资产，强合规、私有化优先、可气隙交付
3. 决策需要可信理由，可解释性与不确定性与预测值同级
4. 性能目标互相冲突，输出 Pareto 前沿而非单一最优
5. 数据异构且脏，接入层需 schema 映射、单位归一与质量规则引擎

**质量属性裁决顺序**：数据安全与可审计 > 可复现可追溯 > 可解释与校准 > 闭环有效性 > 吞吐延迟 > 功能广度。当「上新模型」与「保证每条预测可追溯」冲突时，选后者。

### 技术栈

| 层级 | 选型 |
|---|---|
| 前端 | Vue 3 + TypeScript + ECharts |
| 后端 | Python FastAPI + Celery |
| 特征 / 模型 | RDKit · Mordred · LightGBM / XGBoost · PyTorch Geometric · BoTorch |

## 演进路线

| 阶段 | 重点 | 验收门槛 |
|---|---|---|
| 一期 MVP | 数据治理与 QC、版本化特征工厂、多任务树模型 + 校准区间 + 分组解释 + OOD、约束过滤下的贝叶斯优化、实验状态机与回写、Web 工作台、审计溯源 | **跑通 ≥2 轮完整闭环**，而非模型上线 |
| 二期 | 主动学习全闭环、增量训练与防遗忘、漂移自动重训与回滚、LIMS/ELN 双向对接、RAG 知识中心、多保真度融合 | 实验轮次较基线下降 ≥30% |
| 三期 | 多材料体系配置化扩展、MD/FEA 仿真集成、数字孪生材料卡片、供应链约束、跨项目建模 | 新体系接入靠配置而非新增服务 |

一期明确**不做**：生成模型、GNN、知识图谱、私有 LLM、LIMS 深度对接、跨站点同步（详见架构文档 ADR-12）。

## 开发约定与数据红线

- **配方数据严禁入库**：任何真实配方、实测性能、原材料批次 COA、客户项目数据都不得提交到本仓库。数据目录、表格文件、模型权重、密钥均已由 `.gitignore` 排除，提交前仍需人工确认。
- **不得依赖运行时外网**：私有化 / 气隙交付要求所有镜像、模型权重、依赖包可离线分发；禁止遥测上报与在线许可证校验。
- **预测结果必带溯源**：`model_version + feature_set_version + dataset_snapshot_id` 三元组，缺一不可。
- **特征定义单一来源**：训练与在线推理共用同一份特征代码与版本号，禁止两套实现。
- **文档与代码同步**：架构变更先更新 `docs/ARCHITECTURE.md` 与 ADR 摘要，再改实现，且文档与代码同批提交；破坏性 API 变更升版本并保留旧版至少两个迭代周期。
- **每轮迭代完整闭环**：目标 → ADR → 实现 → 验证证据 → 文档同步 → 上线检查 → 复盘，缺验证证据或文档同步不算完成（见迭代机制文档）。
- **AI 结果不等于可信结果**：语义断言、金丝雀配方集、golden set 回归是上线前置条件；降级时宁可少给功能，不给看似正常的错答案。
- **提交前自检**：`git status` 确认无数据文件、密钥与模型产物；文档类改动不引入无依据的性能数字。
