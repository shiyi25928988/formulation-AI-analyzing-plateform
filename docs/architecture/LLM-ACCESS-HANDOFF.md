# 一页摘要：私有 LLM 接入——从 ADR-12 到 ADR-19 的衔接（供二期团队同步）

> 版本：v1.0 | 2026-11-23 | 依据：`docs/ARCHITECTURE.md` §7.2 / §10（ADR-12、ADR-19）/ §13（R7 风险）
> 用途：二期团队启动知识中心（LLM 接入）时的共识基线。一页读完，细节回架构文档查。

---

## 一、两句话讲清关系

- **ADR-12（一期）**：MVP 不上私有 LLM / 知识图谱 / LIMS 深度对接——一期的瓶颈是数据治理与闭环验证，不是功能广度。
- **ADR-19（二期启用）**：上 LLM 时按什么标准接——分档部署、只做文本层、永不生成配方数值。
- **衔接逻辑**：ADR-12 冻结的是**功能上线时机**，不是**设计边界**。红线和契约在一期就已生效，二期是"往预留插槽里填实现"，不是重新设计。

## 二、二期启动的触发条件（全部满足才切换）

1. 一期验收达成：**跑通 ≥2 轮完整闭环**（不是模型上线）。
2. 数据治理跑稳：QC 规则、血缘追踪、审计链正常运转。
3. 知识库素材就绪：文献抽取流水线有抽检率与准确率指标（否则知识库会静默污染）。

切换流程：按迭代规则走评审，ADR-12 从"一期范围"变更为"二期启用"（理由已经一期验证解除），记入 CHANGELOG。**不算推翻 ADR-12。**

## 三、一期已预埋的三条线（二期直接复用，不改契约）

| 预埋线 | 内容 | 二期收益 |
|---|---|---|
| 契约预埋 | §7.2 职责路由表已写好（数值预测 → 预测服务，禁止交给 LLM） | BFF 与服务边界不动 |
| 数据预埋 | `model_registry` / `lineage_edge` / provenance 审计按"未来多一个文本模型"设计 | LLM 版本与检索来源自动入血缘，审计链不断 |
| 口径预埋 | 档位、许可范围、接口标准已锁定（见下表） | 二期评审只确认型号，不重开架构评审 |

## 四、选型口径（ADR-19 §7.2 表，型号可换、边界不可换）

| 档位 | 推荐型号 | 职责 | 部署 |
|---|---|---|---|
| 主力 | Qwen 32B（INT4） | 知识问答、文献解读、实验方案草案 | 单卡 48G，vLLM |
| 深度推理 | DeepSeek-R1 蒸馏 32B | 失败原因分析、方案推演 | 可与主力共卡 |
| 轻量 | Qwen 8B 级 | 分类、字段抽取、查询改写与路由 | 单卡 24G |
| 检索配套 | BGE-M3 + BGE-reranker | 语义检索与重排（问答质量取决于此层多于主模型） | CPU 可承载 |

约束：仅限**开源可商用权重**（Qwen / Apache-2.0、DeepSeek / MIT、GLM / MIT），API 模型因气隙与数据红线排除；统一 OpenAI 兼容接口；版本固定入 provenance 审计；**不做微调与预训练定制**，领域知识靠 RAG 注入。具体型号二期启动时按当期榜单用真实业务样本 A/B 后定版。

## 五、不可协商的红线

1. **LLM 永不生成配方数值**——性能数字（导热、Tg、剪切强度等）只能来自预测服务，且必须带 uncertainty 与 provenance；LLM 只引用检索到的实测数据。
2. **配方数据不出企业**——LLM 部署于气隙内网，不得出网调用任何外部模型 API；推理全程不出企业边界。
3. **降级时绝不返回低可信结果填补空缺**（§16 口径对 LLM 同样适用）。

## 六、二期团队的待办清单（启动时逐项确认）

- [ ] 核对触发条件三项是否达成（对照一期验收报告）
- [ ] 按当期开源榜单准备候选型号，用真实业务样本做 A/B 定版
- [ ] 算力申请：1×48G（主力 + 深度推理共卡）+ 可选 1×24G（轻量档）

- [ ] 上线前金丝雀基准集（§17）扩入文本层用例，语义断言覆盖"答案必须带引用"
