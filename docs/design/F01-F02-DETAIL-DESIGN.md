# F1 详细设计：预测-实测校准追踪（Calibration Tracking）

> 版本：v0.1（已评审，2026-11-23，software-adhe-review：P0×2 / P1×6 / P2×7 已修）| 上游：`FEATURE-DESIGN-v0.1.md` F1（P1）
> 架构依据：§5（不确定性校准）、§4.3（OOD 两级处置）、§15.2/§16.2（预算与语义断言）、§17.1（验证矩阵）、§7.3（血缘）
> 状态：已评审 → 纳入 R2/R3 实施队列

---

## 1. 背景与目标

架构要求所有预测区间必经 conformal 校准并必返（§5），但产品层没有任何界面展示「模型过去说得准不准」。信任建立是化工场景的核心卖点：**让客户亲眼看到区间覆盖率随数据积累逐步收敛**，比任何口头承诺都有说服力。

**目标**：为每个性能指标提供名义 vs 实测覆盖率的持续追踪，覆盖率异常时给出可操作的处置建议。

**非目标**：不做在线 A/B；不做跨指标合成评分；不做自动重校准执行（只建议）。

## 2. 用户与场景

| 用户 | 场景 | 关注什么 |
|---|---|---|
| 研发主管 | 汇报/验收：「这模型的区间可信吗？」 | 指标级覆盖率曲线 + 收敛趋势 |
| 数据管理员 | 异常处置：「覆盖率怎么掉了？」 | 警示详情、样本下钻、漂移线索 |
| 配方工程师 | 日常：「这个 ±0.07 我能当真吗？」 | 当前模型的覆盖状态徽标 |

## 3. 核心概念与计算口径

### 3.1 样本配对规则

一个**校准样本** = 一次带区间的历史预测 + 一条后续实测结果，配对条件（全部满足）：

1. 血缘关联成立：`lineage_edge` 中该实测所属 `experiment` 采纳了该预测对应的 `formula_version`；
2. 实测质量合规：`test_result.qc_flag = pass` 且 `fidelity = experiment`（F2 档，枚举定义见架构 §3.2；仿真/文献数据**不参与**校准统计）；
3. **失败实验计入**：实测值存在但配方判定失败（如未达标）仍是一条有效标签——覆盖率统计的是「区间是否罩住实测值」，失败结果照样有效（负结果是一等数据的口径延伸）；
4. 时间顺序：实验完成时间晚于预测时间（防止用后来信息校准过去的承诺，point-in-time 原则）；
5. 去重：同一 formula_version 被多次实验验证时，**每次实验都算一个样本**（真实重复性正是要统计的对象），但同一实验对同一指标的多次复测取 QC 通过的最新一条。

### 3.2 覆盖率计算

```
实测覆盖率(c) = #{ 实测值 ∈ 该预测的 conformal c% 区间 } / #{ 配对样本总数 }
```

- 统计档位：c ∈ {50%, 70%, 90%}（架构 §4.3/§5.2 已定义三档输出，禁止另设）。
- 聚合维度：**按指标独立计算**（metric_code），跨指标不合成。
- 时间窗口：全历史 + 滚动近 3 个月两组，用于展示收敛趋势。

### 3.3 警示阈值与处置建议

| 状态 | 条件 | 展示 | 处置建议 |
|---|---|---|---|
| 正常 | 实测 ≥ 名义 − 5pp | 绿 | — |
| 关注 | 实测 < 名义 − 5pp | 黄 | 提示「关注分布漂移，联动数据质量看板 F4」 |
| 异常 | 实测 < 名义 − 10pp | 红 | 建议「触发重校准流程（§5 校准服务）」，给出异常样本清单入口 |
| 样本不足 | n < 30 | 灰 | 明示「样本不足，仅供参考」，**不画曲线**（拒绝给出误导图形） |
| 无数据 | n = 0 | 空 | 显示「尚无配对样本」，附引导（先完成一轮闭环回写） |

> 与防静默失败口径一致：宁可明示不可信，绝不展示看似合理的曲线。

## 4. 界面设计

### 4.1 信息架构

```
配方工作台
 └── 校准追踪（子页入口，与配方编辑并列）
      ├── 指标选择器（tab：导热 / Tg / 剪切强度 / …，来自 metric_definition）
      ├── 校准曲线图（名义 vs 实测，对角线为理想；当前模型版本标记）
      ├── 收敛趋势（按月时间序列，全历史 vs 近 3 个月双线）
      └── 样本明细表（可下钻：预测 ID / 实验 ID / 实测值 / 是否罩住 / 日期）
```

### 4.2 组件清单（新增，复用既有令牌）

| 组件 | 变体 | 说明 |
|---|---|---|
| `CalibChart` | normal / red / insufficient / empty | 区间图；insufficient 变体显示灰色说明卡而非坐标轴 |
| `CoverageTrend` | normal / warning | 双线时间序列，黄区带标注 |
| `CalibStatusBadge` | 5 态 | 与 §3.3 状态一一对应，配色用现有 success/warn/danger/locked 令牌 |
| `SampleTable` | — | 明细下钻，行点击跳转实验卡（实验管理看板） |

### 4.3 交互要点

- 曲线图 hover 显示该档位样本数 n；点击数据点 → 过滤样本明细表。
- 「处置建议」为可执行动作：红态提供「发起重校准」按钮（走 §5 校准服务，需管理员角色，操作入审计）。
- 页脚常驻 provenance：`模型版本 + 特征集 + 数据快照` 三元组 + 统计计算时间 `computed_at`（物化数据非实时，防止误读为当日实时值），模型版本切换后历史曲线保留可查（按版本分线）。

                  { "level": 0.5, "nominal": 0.5, "empirical": 0.49, "n": 84 } ],

## 6. 数据与查询

- **在线查询不走重口径**：覆盖率统计涉及 `prediction_log` × `test_result` × `lineage_edge` 三表关联，线上实时算会击穿 P95 预算（§15）。设计为**定时物化**：Celery 夜间任务计算并写入物化表 `calib_stat(metric_code, coverage_level, window, n, empirical, model_version, snapshot_id, computed_at)`，界面只读物化表；重校准任务完成时增量刷新。
- **归属服务**：校准统计与 `/calibration/*` 接口归属 **model-lifecycle-svc**（训练评估域，`calib_stat` 由其物化写入）；`prediction-svc` 保持无状态、不写库的服务边界不变。
- `calib_stat` 为**新增表**，随 R2 的 B01 DDL 一并给出并评审（不改变既有表定义）。
- 模型版本维度保留历史：物化表按 model_version 分行，支持「版本切换后历史曲线可查」。

## 7. 边界与异常

| 情况 | 处理 |
|---|---|
| 预测为 severe OOD（拒答，无区间） | 不参与统计（无区间可罩）；advisory 级 OOD 预测带区间，正常参与统计并在明细行标记（两级口径见架构 §4.3） |
| 测试标准变更（同指标不同标准） | 按 `test_standard` 分组统计，不跨标准混合；标准数 >1 时曲线分线展示 |
| 血缘断裂（预测记录缺失） | 该样本剔除并计入「血缘缺失计数」，超过 5% 时在看板警示（指向 F4） |
| 指标方向为 target 型（区间达标制） | 覆盖率口径不变（区间罩住实测值），达标判定另行展示，不混入本页 |

## 8. 验收标准

1. 能按指标查看 90/70/50 三档名义 vs 实测覆盖率及月度趋势；
2. n<30 显式「样本不足」，n=0 显式空态引导，两者均不画曲线；
3. 红态处置建议可发起重校准（管理员角色校验 + 审计留痕）；
4. 样本明细可下钻到实验卡；失败实验正确计入统计；
5. 全接口带 provenance；界面 P95 < 2s（物化表命中）。

# F2 详细设计：配方版本对比（Version Diff）

> 版本：v0.1（已评审，2026-11-23，software-adhe-review）| 上游：`FEATURE-DESIGN-v0.1.md` F2（P1）
> 架构依据：§3.2（formula_version 不可变快照与 DECIMAL 配比规则）、§7.3（血缘双向查询）、§8（ABAC）
> 状态：已评审 → 纳入 R2/R3 实施队列

---

## 1. 背景与目标

配方版本管理已在领域模型中落地（`formula_version` / `formula_component` 不可变快照），原型也出现了「F-2026-0184 v3（草稿）」版本号，但「v2 和 v3 到底差在哪」没有产品承接。配方工程师迭代配比后最自然的动作就是对比，这个缺口每天都会被撞到。

**目标**：任意两个版本的双栏差异对比，差异联动预测对照、实测对照与血缘跳转。

**非目标**：不做三方合并对比；不做「哪个差异导致性能变化」的自动归因（组分强共线下归因不可信，交给工作台分组归因 §5.2；F1 异常样本下钻可辅助定位）；一期不做跨配方对比。

## 2. 用户与场景

| 用户 | 场景 |
|---|---|
| 配方工程师 | 「我把填料从 180 调到 195，其他指标会怎么变？上一版实测和这版差多少？」 |
| 研发主管 | 审阅：「这次改动的依据是什么？影响面多大？」（血缘跳转） |
| 数据管理员 | 审计：「对比报告作为交付附件导出」（走审批 + 水印） |

## 3. 对比口径（Diff 规则）

### 3.1 组分差异

| 差异类型 | 判定规则 | 展示 |
|---|---|---|
| 新增 | 目标版有、基线版无 | 绿底行，仅右栏有值 |
| 移除 | 基线版有、目标版无 | 红底行，仅左栏有值 |
| 修改 | 同一材料且配比差 > **0.01 phr**（DECIMAL 比较，禁浮点——§3.2 口径） | 黄底行，双栏值 + 差值徽标（+15.0） |
| 不变 | 差 ≤ 0.01 phr | 无底色 |

- 匹配键：`material_id + batch_id + role`；同材料改角色视为「移除 + 新增」（语义即如此，不做模糊匹配）。
- 组排序：按差异类型（修改 > 新增 > 移除 > 不变）+ 角色分组，差异置顶。

### 3.2 工艺参数差异

固化温度/时间/后固化等键值对逐一对比，数值差 > 0 视为修改；展示规则同上。

### 3.3 联动对照

差异结果之上叠加两层对照（各自独立展示，不做交叉归因）：

1. **预测对照**：两版各自最新一次预测的各指标（值 ± 区间并排），标注模型版本是否同版——跨模型版本的对比要提示「预测差异可能包含模型迭代因素」；
2. **实测对照**：两版均有回写实验时展示实测值与实验号；只有一方有则显示单侧并提示「另一版本尚无实测」。

## 4. 界面设计

### 4.1 信息架构

```
配方工作台 → 「对比版本」按钮
 └── 对比视图（全屏，脱离编辑态）
      ├── 版本选择器（左基线 / 右目标；同配方版本列表，含版本时间与状态）
      ├── 差异汇总条（N 处修改 · M 新增 · K 移除；工艺参数 X 处）
      ├── 组分双栏 Diff 表（§3.1 规则渲染）
      ├── 工艺参数 Diff（折叠区，默认展开有差异项）
      ├── 预测对照卡（指标行复用 MetricCard，双值双区间）
      ├── 实测对照卡（有则显示，含实验号跳转）
      └── 操作条：血缘跳转（「查看该变化的预测/实验影响面」）· 导出对比报告（审批 + 水印）
```

### 4.2 组件清单（新增）

| 组件 | 变体 | 说明 |
|---|---|---|
| `DiffTable` | 组分 / 工艺 | 行态：changed(黄) / added(绿) / removed(红) / unchanged；差值徽标用 tabular-nums |
| `SideBySideMetricRow` | 预测 / 实测 | 复用 MetricCard 视觉，双值双区间条 |
| `VersionPicker` | — | 下拉 + 版本元信息（时间、状态、创建人） |
| `CrossModelHint` | — | 跨模型版本对比时固定出现的说明条（黄） |

## 5. 交互流程

```
选择基线/目标版本 → 服务端计算 diff（唯一权威口径）→ 渲染
   ├─ 任一版本无预测 → 预测对照卡显示「未预测」引导
   ├─ 版本数过多 → 版本选择器支持按时间筛选与搜索
   └─ 导出报告 → ExportRequested 事件 → 双人审批 → 水印 PDF/CSV
```

## 6. API 契约

```
GET /api/v1/formulas/{formula_id}/versions?fields=meta
  → [{ "version": 3, "state": "draft", "created_by": "研A", "created_at": "…" }, …]

GET /api/v1/formulas/{formula_id}/diff?from=2&to=3
  → { "from": {…meta}, "to": {…meta},
      "same_model_version": false,
      "summary": { "changed": 1, "added": 1, "removed": 0, "process_changed": 1 },
      "components": [ { "type": "changed", "material": "球形硅微粉", "role": "填料",
                        "from": "180.0", "to": "195.0", "delta": "+15.0" }, … ],
      "process":  [ { "key": "cure_temp", "from": "150", "to": "165" } ],
      "predictions": { "from": { "metric": {…}, "interval": […], "model_version": "v1.2.0" } | null,
                       "to":   { …, "model_version": "v1.3.0" } },
      "measurements": { "from": { "experiment_id": "EXP-0871", "value": 0.81 } | null, "to": … | null },
      "lineage_ref": "/api/v1/lineage?formula_version=3" }
```

> phr 数值一律以**字符串定点**传输（如 `"195.0"`），避免 JSON 浮点精度问题（§3.2 DECIMAL 口径），上例从之。

约束：diff 一律**服务端计算**（DECIMAL 精度与匹配规则唯一权威，禁止前端自行 diff）；响应带 provenance；权限校验按 ABAC——任一版本超出当前用户可见密级即 403 并审计。

## 7. 数据与查询

- 组分表为不可变快照（§3.2），diff 为纯内存计算，`formula_component` 按两个 version_id 各取一次全量即可，无增量负担；
- 大组分表（>200 行）场景：diff 本身 O(n)，渲染分页由前端处理，接口不分页（保证 summary 与明细一致）；
- 血缘跳转复用 §7.3 双向查询接口，不新增后端能力。

## 8. 边界与异常

| 情况 | 处理 |
|---|---|
| 对比对象跨配方 | 一期拒绝（仅同配方版本间），UI 不可达 |
| 草稿版 vs 草稿版 | 允许（工程师迭代对比高频场景） |
| 任一版本密级不可见 | 403 + 审计事件 |
| 预测来自不同模型版本 | 显示 CrossModelHint，不合并差异结论 |
| 实测对照存在失败实验 | 展示失败标记（全量留痕口径），不隐藏 |

## 9. 验收标准

1. 任意两个版本的组分/工艺 diff 正确，匹配与容差符合 §3.1（DECIMAL 比较）；
2. 预测对照显示双值双区间并标注模型版本；跨模型版本出现提示条；
3. 血缘跳转可达影响面视图；导出报告走双人审批 + 水印；
4. 越权对比被拒绝且留审计；服务端 diff 为唯一口径（前端无独立 diff 逻辑）。
